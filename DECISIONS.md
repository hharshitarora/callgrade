# Decisions

Why callgrade works the way it does. Each entry is the choice, the alternative, and the reason.

## A 0 to 2 scale, not 1 to 10

Three levels with a written description for each. People agree with each other
far more often on "pass, partial, fail" than on a 7 versus an 8, and a judge
can only be checked against people who agree with each other. A ten-point scale
would look more precise and be less reliable.

## Reason first, score second

The verdict schema puts `reason` before `score`, and the prompt says so. A model
that commits to a number first tends to write a reason that defends it.

## Timing is measured, not judged

Latency, talk-over and dead air come from timestamps in plain code. The judge is
shown the results as facts. Asking a model "was the agent slow?" over a
transcript invites a guess about something a subtraction answers exactly.

## Unmeasured beats a guess

Bland gives turn starts but no ends; a Bolna execution gives no times at all.
Rather than estimating durations from word counts, a check that lacks the data
reports `unmeasured`. A report that says "pass" on a call it could not measure
is worse than one that admits it.

## Guardrails block

One invented refund policy can cost more than a hundred slightly awkward
greetings, so a total score alone hides the call that matters most. A rubric
dimension marked `blocker` flags the call whenever it scores the minimum,
whatever the total, and `--fail-on-blocker` turns that into a failed build.

## The judge never reads the platform's summary

Platforms attach their own summary and analysis to a call. The adapters drop
them. A judge that reads another model's summary is grading the summary, and two
models agreeing with each other is not evidence either is right.

## Agreement is measured with weighted kappa

Exact agreement alone flatters a judge on a set of mostly good calls: always
answering 2 scores well. Cohen's kappa corrects for that, and quadratic weights
make a 0 versus 2 disagreement cost more than a 0 versus 1, which matches how a
person would read the miss.

## Haiku is the default judge

Grading is a reading task with a fixed rubric, and teams grade thousands of
calls. At about $0.0005 a call the default is cheap enough to run on every call
and every prompt change. The agreement measurements exist so a team can check
whether a bigger model earns its price on their own calls, instead of assuming.

## The test set is synthetic and generated

Real calls carry real people's names and numbers, so they cannot ship in a
public repo. The 20 calls in `examples/` are written for a made-up letting
agency, generated by `scripts/make_testset.py` so the timing is exact and the
files are reproducible byte for byte. Each planted failure is written so a
careful person would flag it without being told where to look. CI fails if the
committed files drift from the generator.

## One file per call, JSON

The callgrade format is deliberately plain: a list of turns with a speaker, the
text and optional times. Anyone can write a converter for a platform that is not
supported yet without reading this codebase.
